# Experiments

Benchmarks and tests for the tensor network MPS decoder on QLDPC codes.

## Environment Setup

### Prerequisites

- Python >= 3.11
- [uv](https://docs.astral.sh/uv/) package manager

### Create virtual environment and install dependencies

```bash
# Install uv (if not already installed)
curl -LsSf https://astral.sh/uv/install.sh | sh
source $HOME/.local/bin/env

# Create venv with Python 3.12
uv venv .venv-mps --python 3.12

# Install core dependencies
uv pip install --python .venv-mps/bin/python \
    numpy scipy quimb autoray matplotlib pytest

# Install decoder dependencies
uv pip install --python .venv-mps/bin/python \
    ldpc stim PyMatching cotengra

# (GPU only) Install cupy and cudaq
uv pip install --python .venv-mps/bin/python cupy-cuda12x cudaq
```

### Verify installation

```bash
.venv-mps/bin/python -c "import quimb; import numpy; print('OK')"
```

## Running Tests

All tests use the `cudaq_qec` Python package from the local `cudaqx/` tree. Set `PYTHONPATH` accordingly:

```bash
export PYTHONPATH=cudaqx/libs/qec/python:.
```

### Task 6: Ablation study -- decomposition method comparison

Compares three decomposition approaches: Naive Direct contraction, Quimb compress_all, and Our MPS decomposition.

**Step 1: Cost estimation (lightweight, no actual contraction)**

```bash
PYTHONPATH=cudaqx/libs/qec/python:. python3 experiments/tests/estimate_ablation_cost.py
```

Produces `experiments/results/ablation_cost_estimates.json` with estimated FLOPs, peak memory, contraction width for all 9 ISCA codes.

**Step 2: Full ablation run (actual decode, slow for large codes)**

```bash
# Smoke test (1 shot, our_mps only, QCC_90)
PYTHONPATH=cudaqx/libs/qec/python:. python3 -m pytest experiments/tests/test_ablation_decomposition.py -v -s

# Full run (32 shots, all methods, all codes)
PYTHONPATH=cudaqx/libs/qec/python:. python3 experiments/tests/test_ablation_decomposition.py
```

Produces `experiments/results/ablation_decomposition_results.json`.

> **Note**: Naive/Quimb methods on large codes (QCC_108, QCC_144) require >100GB memory and may OOM. Use `--methods our_mps` or the cost estimation script instead.

**Step 3: Plot results**

```bash
# Plot from cost estimation (recommended)
PYTHONPATH=. python3 experiments/plots/plot_ablation_decomposition.py \
    --input experiments/results/ablation_cost_estimates.json

# Plot from full ablation run
PYTHONPATH=. python3 experiments/plots/plot_ablation_decomposition.py \
    --input experiments/results/ablation_decomposition_results.json

# Auto-detect (plots both if available)
PYTHONPATH=. python3 experiments/plots/plot_ablation_decomposition.py
```

Output (PDF + PNG + SVG) saved to `experiments/plots/out/ablation_decomposition/`:
- `ablation_cost_comparison` -- FLOPs and peak memory bar chart
- `ablation_width_storage` -- contraction width and TN/MPS storage
- `ablation_flops_scaling` -- FLOPs vs code size N (line plot)

## Decoder Backends

The MPS decoder (`tensor_network_mps_decoder`) uses three backends in priority order:

1. **OneDChainMPS** -- 1D chain extraction (surface/toric codes)
2. **CompressedTNDecoder** -- fully contracted MPS for QLDPC codes where 1D chain topology is unavailable
3. **Exact contraction fallback** -- full TN contraction via cutensornet (GPU) or torch (CPU)

For QLDPC codes (BB, HP), the CompressedTNDecoder is the primary online decode path (~0.3ms/shot on CPU).
